# 系统形态分析框架

> 日期：2026-05-13
> 状态：设计稿

---

## 一、分析目的

通过对比不同知识库实现系统的形态特征，识别 Marginalia 的设计选择和权衡。

## 二、分析维度

| 维度 | 含义 |
|------|------|
| 存储模型 | 知识的持久化方式（文件/数据库/向量） |
| 驱动模型 | 什么触发知识操作（Hook/协议/手动） |
| 类型模型 | 知识节点的分类方式（固定/灵活/无） |
| 质量模型 | 质量保障的手段（脚本/自检/无） |
| 搜索模型 | 知识检索的方式（语义/结构/全文） |
| 规模模型 | 系统的扩展策略（分片/层级/无） |

## 三、对比对象

1. **Karpathy LLM Wiki** - 极简模式
2. **mem0** - API 驱动
3. **claude-mem** - 文件驱动
4. **WeKnora** - 结构化
5. **superpowers** - Hook 驱动
6. **Marginalia (GPT54)** - 协议驱动

## 四、分析方法

对每个对比对象，按六个维度分别评估：

- 设计选择（做了什么决定）
- 权衡（放弃了什么）
- 适用场景（什么情况下合适）
- 局限（什么情况下不合适）

结果汇总为形态矩阵，用于指导 Marginalia 的设计决策。

## 五、输出格式

每个对比对象一份分析报告，最终一份综合对比表。
