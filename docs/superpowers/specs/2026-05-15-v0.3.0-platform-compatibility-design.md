# Marginalia v0.3.0 — 平台兼容性设计

> 日期: 2026-05-15
> 状态: 草稿
> 版本: v0.2.1 → v0.3.0

## 背景

OpenClaw 实地反馈报告（docs/feedback/openclaw-field-report-2026-05-15.md）在 15 天生产部署后（153 页、18 个会话、605 条 cron 运行记录）发现了三个问题：

1. "收工规则"从未自行执行（0/18 次）——演员-控制器混淆
2. audit.py 输出不适用于 CI/cron 场景——缺少 brief 模式和 exit-code-only 模式
3. 缺少平台集成指引——用户创建了 40M token 的失败 cron 实验

核心发现：Marginalia 的三原则（同位/无损/解耦）和工具链（init/audit/verify）在跨平台部署中已完全验证通过。问题出在执行模型和输出格式，不在平台兼容性。

## 决策：不分叉

Marginalia 保持单一代码库。兼容性在协议层（Markdown + wikilinks），不在平台集成层。平台特定集成以文档说明，不以代码实现。

理由：

- 三原则在 OpenClaw 上已验证通过（实地报告评分 5/5）
- 零依赖脚本在任何 Python 3 环境均可运行
- 分叉违反"解耦"原则并增加维护负担
- 实地报告的问题属于执行模型问题，不属于平台不兼容

## 改动

### 1. rules.md — 修复执行模型（事件驱动审计提醒）

**文件**: schema/rules.md

**控制论依据**：实地数据显示收工时运行 audit.py 的执行率是 0/18 (0%)。原因是演员-控制器混淆——AI 在完成工作后不会主动切换到维护模式。

**触发策略**：事件驱动。AI 在正常读取知识库时如发现断链、孤儿页等异常，主动提醒用户运行 audit.py。不做时间驱动检查（"index.md 是否有变更"条件太宽，几乎每会话都触发，信噪比低）。

**当前**（读取规则 + 收工规则）:
```
## 读取规则
1. 每次对话开始，先读 wiki/index.md 了解知识库全貌
2. 遇到相关知识话题，沿 [[wikilink]] 读取相关页面
3. 读取页面时连同页内批注一起读取

## 收工规则
1. 更新 wiki/index.md（如有新页面）
2. 在相关页面添加批注：> [!memo] YYYY-MM-DD 内容
3. 运行 `python3 scripts/audit.py --root wiki/`，处理发现的问题
```

**改为**:
```
## 读取规则
1. 每次对话开始，先读 wiki/index.md 了解知识库全貌
2. 遇到相关知识话题，沿 [[wikilink]] 读取相关页面
3. 读取页面时连同页内批注一起读取
4. 如在读取中发现断链、孤儿页或其他异常，提醒用户："发现知识库问题，建议运行 audit.py 检查"

## 收工规则
1. 更新 wiki/index.md（如有新页面）
2. 在相关页面添加批注：> [!memo] YYYY-MM-DD 内容
```

关键变化：
- 读取规则新增第 4 条：事件驱动提醒——只在 AI 实际发现问题时触发
- 收工规则删除第 3 条（"运行 audit.py"）——0% 可靠的触发点
- 零噪声：AI 不会每会话都提醒，只在有真实信号时提醒
- 符合"同位"原则：AI 在读取知识时顺便发现问题

**改动行数**: ~5 行

### 2. audit.py — 增加 CI 友好输出模式

**文件**: scripts/audit.py

**新增 CLI 参数**:

| 参数 | 行为 |
|------|------|
| `--brief` | 只输出 `P0:X P1:X P2:X`（单行） |
| `--exit-code-only` | 无标准输出。退出码：P0>0→2，P1>0→1，否则→0 |

这两个模式支持：
- `--brief`：适合人类阅读的 cron 通知或 OpenClaw heartbeat 集成
- `--exit-code-only`：CI 流水线集成（非零退出码 = 失败）
- 组合使用：`--brief --exit-code-only` 同时输出摘要和设置退出码

实现：
- 在 `main()` 的参数解析中增加 `--brief` 和 `--exit-code-only`
- 根据 mode 格式化输出
- 退出码逻辑：先检查 P0（最高严重度），再检查 P1

**改动行数**: ~20 行

### 3. README.md — 平台集成说明

**文件**: README.md

**新增章节**："平台集成"（在"三阶段工作流"之后）

内容：
- 说明 Marginalia 工具在协议层兼容（Markdown + 零依赖 Python）
- 各平台运行方式：
  - Claude Code：手动 `python3 scripts/audit.py --root wiki/`
  - OpenClaw：使用 `--brief` 模式配合 heartbeat 或低频 cron（每日最多一次）
  - CI/CD：使用 `--exit-code-only` 在流水线中集成

**改动行数**: ~15 行
